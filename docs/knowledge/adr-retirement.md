# ADRの新規作成をやめた

このプロジェクト（文書体系というフレームワークを作る側）は、ADR-0001〜0013を作った後、新規のADR作成をやめた。

理由: ADR-0005+0006+0007、ADR-0010+0012のように、1つの決定を正しく理解するために複数のADRを突き合わせる必要がある補正チェーンが繰り返し発生した。ADR-0008は自己言及的な数値の数え間違いを起こし、本文が不変であるためREADME.mdでの訂正が必要になった。個人開発・小規模チームというこのプロジェクトの規模に対し、不変性・連番・Status/supersede機構という一式は重すぎた。

以後の運用: `documentation-rules`の「決定・経緯を書く際の分量基準」に従う。

既存のADR-0001〜0013、`docs/adr/`、`docs/adr/TEMPLATE.md`は凍結し、削除しない（既存の参照を無効にしないため）。

却下した代替案: ADR自体の基準を緩め、より軽い決定にも適用範囲を広げる案。基準を緩めた時点で「アーキテクチャ上重要な決定の記録」というADR本来の性質と乖離し、名前と実態がずれるため却下した。

範囲: この決定はrootにのみ適用する。フレームワークを使う側のプロジェクトが独自にADRを採用するかどうかは、そのプロジェクトの判断に委ねる（`.dev/template-src/SETUP.md`に推奨として記載。同ファイルはテンプレート配布時に`project-template/SETUP.md`としてビルドされる）。
