# project-template/を同期ではなくビルドで作る

rootと`project-template/`は多くのファイルが同一内容だが、一部は本質的に内容が異なる。一括で`cp`した結果、異なるべきファイルを誤って上書きする事故が2回発生した。さらに、テンプレート固有の一次情報（`SETUP.md`、テンプレート版`docs/index.md`）はroot側に対応する元データを持たず、他の共有ファイルとは性質が異なる。これらを`project-template/`に直接置いたまま同期スクリプトを繰り返し実行すると、ファイルごとに「同期対象か手動維持か」を判断する必要が生じる。

決定: `.dev/build-template.sh`を同期ではなくビルドとして設計し、`project-template/`を実行のたびに丸ごと削除して作り直す。テンプレート固有の一次情報は`.dev/template-src/`にソースとして置き、rootと内容が同一であるべきファイルは許可リストに列挙する。

理由: 毎回ゼロから組み立てれば、「同期対象か手動維持か」という判断自体が消える。判断が残る限り、誤上書きは再発しうる。

却下した代替案: 差分更新型の同期スクリプトを維持し、異なるべきファイルを除外リストで守る案。除外リストの更新漏れが誤上書きの原因そのものであり、同じ失敗の形が残るため却下した。

あわせて、テンプレート版`AGENTS.md`を薄い`AGENTS.md`と`docs/system.md`に分割した。理由: root版をそのまま配布すると、配布先プロジェクトが自分固有の指示（ビルド・テスト手順、コーディング規約等、AGENTS.mdエコシステムで一般的に書かれる内容）を書く場所を失う。
