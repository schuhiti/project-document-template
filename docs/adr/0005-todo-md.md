# ADR-0005: セッション内の実行項目を保持する`.dev/todo.md`を新設する

## Context
GitHub Issueの粒度は「doneの定義が明確な単位」と確定したが、doneが明確でもGitHub Issueとして起票するには小さすぎる項目（同一セッション内で解消し、セッションをまたいで追跡する価値のないもの）がある。一方、Handoffはセッション/コンテキスト境界でのみ更新するため（ADR-0003）、セッション内で思いついた小さな実行項目を都度書き留める場所が無い。

## Decision
`.dev/todo.md`を新設し、セッション内の小さな実行項目（doneは明確だが、セッションをまたぐ追跡価値が無いもの）を保持する。Handoffと異なり、セッション内で自由に追記・削除してよい。完了した項目は記録を残さず削除する（成功した定型作業を記録しないというADR-0004と同じ考え方）。セッション境界（Handoff更新のタイミング、ADR-0003）で、まだ残っている項目は、セッションをまたぐ価値があればGitHub Issueへ、Handoffの「次にやること」で引き継ぐべきならそちらへ昇格し、`.dev/todo.md`自体は空に戻す。

## Consequences
セッション内の細かい実行項目を、GitHub Issueの起票コストやHandoffの更新境界を気にせず自由に書き留められる。一方、文書種別がまた1つ増え、境界での棚卸しを怠ると、完了していない項目が失われるリスクがある。

## Alternatives Considered
GitHub Issueで代用する案は、AIエージェントとのローカルなやり取りにおいて起票コストが小さな項目には見合わないため却下した。Handoffに直接書く案は、ADR-0003のセッション境界更新の原則と矛盾するため却下した。
