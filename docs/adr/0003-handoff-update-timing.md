# ADR-0003: Handoffの作成・更新はセッション/コンテキストの境界でのみ行う

## Context
本検討中、Handoffがほぼ毎ターン更新されており、作成・更新のタイミングが定義されていなかった。Handoffは「継続性のためだけの文書」と位置づけているが、更新頻度が細かすぎると実質的に作業ログ・議事録に近い運用になり、以前是正した肥大化・二重管理の問題を別の形で再発させかねない。

## Decision
Handoffの作成・更新は、次のいずれかに該当する境界でのみ行う: (1) セッション/作業を中断・終了する直前 (2) コンテキストが圧縮される直前、またはされたことに気づいた直後 (3) 再開時に知らないと支障が出るような大きな決定・方針転換があった時。同一セッション内の細かい進行では更新しない。作成のタイミングも同じ基準で、最初に該当した時点で作ればよく、あらかじめ空ファイルを用意する必要はない。

## Consequences
更新頻度が下がり、Handoffが本来の「境界をまたぐための最小限の状態」に留まりやすくなる。一方、境界の判断は主観に委ねられる部分があり、更新を怠って直前の変化が失われるリスクも残る。

## Alternatives Considered
毎ターン更新する案は、本検討中に実際に採っていたが、作業ログ化を招くため却下した。
