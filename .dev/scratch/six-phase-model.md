# 検討: 想定する作業の6フェーズモデル

①前提を固める → ②検討・議論を進める → ③文書化・Skill化・ツール連携する → ④設計する → ⑤作業を計画する → ⑥作業を進める

検討開始時にそのまま前提として提示されたものを使い続けているだけで、この分割が実態に合っているかは一度も検証していない。

トリガー: 実際の作業サイクルを何度か回した後、この分割が機能しているか振り返る。機能していれば `docs/premise.md` へ確定として昇格、そうでなければ書き換える。
